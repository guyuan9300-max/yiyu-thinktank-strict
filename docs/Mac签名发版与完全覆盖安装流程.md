# Mac 签名发版与完全覆盖安装流程

这是一套可重复执行的正式发版流程，不绑定某个具体版本或某台临时电脑。

## 一条命令完成

确定新版本号后，在严格新版仓库执行：

```bash
npm run release:mac-signed -- 0.29.6 "$HOME/Desktop/0.29.6"
```

把示例中的 `0.29.6` 换成实际新版本号即可。脚本固定按以下顺序执行：

1. 同步修改 `package.json` 和 `package-lock.json` 的版本号；
2. 检查严格88表规则、仓库身份、前端与主进程构建；
3. 提交当前阶段修改并先推送到远端 `main`；
4. 确认本地与远端 `main` 是同一个提交；
5. 从当前 Mac 钥匙串取得有效签名，构建签名 App 和签名 DMG；
6. 检查 DMG 只能包含“安装或更新”程序，禁止退回拖拽安装；
7. 在隔离目录造一个旧版，调用 DMG 内真正的安装器完成覆盖；
8. 验证新版版本号、Bundle ID、签名均正确，并确认旧内容、旧副本和更新临时文件已清除；
9. 把最终 DMG 复制到指定输出目录并给出 SHA-256。

任一步失败都会停止，不会把“能构建”冒充成“能发布”。

## 签名从哪里取得

签名来自当前 Mac 的“钥匙串访问”中的有效 `Developer ID Application` 证书及其私钥。脚本会自动查找，不在指令里写死某个人名。

可用下面的命令自行检查：

```bash
security find-identity -v -p codesigning
```

若没有有效证书，需要由 Apple Developer 账号持有人从有证书的 Mac 导出含私钥的 `.p12`，导入当前 Mac 的“登录”钥匙串。不要把证书、私钥或密码提交到 Git。

如一台 Mac 同时有多个有效签名，可显式指定：

```bash
MAC_CODESIGN_IDENTITY="Developer ID Application: 名称 (TEAMID)" \
  npm run release:mac-signed -- 0.29.6 "$HOME/Desktop/0.29.6"
```

## 用户安装方式

用户下载并打开 DMG 后：

1. 双击“安装或更新益语智库AI”；
2. 点击“安装并打开”；
3. 安装器自动退出正在运行的旧版，找到扩展坞实际指向的软件，原位完整替换并打开新版。

用户无需拖到“应用程序”，无需自己删除旧版，也不需要 Node.js、npm 或开发环境。

## 每次发版的最终判定

以下条件必须同时满足：

- 远端 `main` 与本机发版提交一致；
- DMG、安装器和内嵌 App 的签名验证通过；
- DMG 内没有旧式“App + Applications”拖拽布局；
- 隔离旧版已被 DMG 内安装器真实覆盖为新版本；
- 原旧版标记、备份副本、更新临时副本均不存在；
- 最终文件名、内嵌版本号和本轮新版本号一致。

脚本全部通过后，才可把 DMG 上传到官网版本发布后台。
