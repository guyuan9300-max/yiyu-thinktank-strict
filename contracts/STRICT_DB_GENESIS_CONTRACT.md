# 益语智库严格新版数据库创世合同 v1

> 历史合同：已由 `STRICT_PHYSICAL_SCHEMA_CONTRACT_V7.md` 的蓝图 88 表物理合同取代，仅保留为 2026-07-29 施工决策证据，不再作为活动库建表依据。

状态：`FROZEN_FOR_IMPLEMENTATION`

冻结日期：2026-07-29

## 1. 合同用途

本合同定义“严格新版”的最小物理数据库边界。它不是现有混合数据库的精简版，也不是把旧表换名后继续运行。只有同时满足本合同、两个 schema manifest 和验收清单的构建，才可自称严格新版。

参考资料是《益语智库数据库重构_完整续跑包_20260723》中的逻辑蓝图、业务合同、旧路径学习账本与审计规则。该资料处于 NO-GO 阶段，因此只用于提炼边界，不复制其中数据库、迁移脚本或运行源码。

## 2. 创世范围

第一份严格新版数据库只承载以下底座：

- 本机设备、工作空间与组织稳定绑定。
- 云端账号、组织、成员、部门、权限和邀请码。
- 组织统一 AI 配置的安全保存与下发授权。
- 命令、幂等、CAS、outbox/inbox、审计、恢复与对象存储登记。
- 可重建的本机身份和组织投影。

任务、客户、项目、事件线、文档、知识、报告、成长、复盘、情报等业务域暂不进入创世数据库。完整软件可以保留这些前端入口，但在相应业务合同落地前必须显示“尚未接通新版数据”，不得返回假空列表、读取旧库或临时建表。

## 3. 两个物理数据库

### 3.1 本地数据库

本地数据库角色是设备运行状态、工作空间绑定、可重建投影和可靠命令队列。它不是组织协作事实的权威来源。

唯一允许的物理表集合由 `strict-local-schema-manifest.v1.json` 冻结。运行时出现白名单外表即判定构建污染。

本地数据库不得保存：

- 组织业务权威事实。
- access token、refresh token、密码或 AI API Key 明文。
- 以组织名、云地址或当前用户为归属键的数据。
- 旧数据库兼容表、影子业务表或旧表 fallback。

系统密钥只进入操作系统密钥库；SQLite 只保存不可逆指纹和密钥引用。

### 3.2 组织云数据库

组织云数据库角色是身份、组织、授权和可靠命令底座的权威来源。

唯一允许的物理表集合由 `strict-cloud-schema-manifest.v1.json` 冻结。业务域表必须在后续独立合同冻结后，以 manifest 版本升级方式加入，不得由功能代码运行时创建。

益语智库云和星丛云必须分别使用独立数据库、独立对象存储命名空间和独立 `cloud_instance_id`。两者不得共享业务行、密钥或迁移状态。

## 4. 数据库与构建身份

每个数据库必须在 `meta_schema_builds` 中保存且仅保存一个当前激活身份：

- `schema_family`
- `schema_contract_version`
- `schema_manifest_sha256`
- `migration_set_sha256`
- `build_id`
- `created_at`
- `activated_at`
- `database_role`

`PRAGMA user_version` 只作 SQLite 辅助版本，不足以证明兼容。程序启动必须同时核验数据库角色、schema family、manifest 哈希和迁移集合哈希。

同一个版本号不得对应两套不同物理结构。manifest 或迁移变化必须产生新的 build identity。

## 5. 稳定身份

以下身份不可互相替代：

- 本地工作空间：`sandbox_id`
- 云实例：`cloud_instance_id`
- 组织：`organization_id`
- 人：`principal_id`
- 组织成员关系：`membership_id`
- 部门：`department_id`
- 设备：`device_id`
- 命令：`command_id`
- 操作：`operation_id`
- 对象存储资源：`storage_object_id`

`cloud_api_url` 只是连接入口。手机号、邮箱、姓名、组织名、部门名和项目名都是可变属性，禁止作为关系键或归属推断依据。

本地组织绑定必须同时匹配 `sandbox_id + cloud_instance_id + organization_id`。任一身份不一致都停止同步，不得退回其他空间或复用其他空间密钥。

## 6. 客户端与云端握手

登录、启动恢复和切换空间必须先完成严格握手。云端至少返回：

- `cloudInstanceId`
- `organizationId`
- `principalId`
- `membershipId`
- `schemaFamily`
- `schemaContractVersion`
- `schemaManifestSha256`
- `buildId`
- `capabilities`

客户端必须核对目标 sandbox 的固定身份。数据库合同不兼容时进入 `schema_incompatible`，只允许诊断、备份和升级，不允许业务写入。

云端未声明的业务 capability 一律视为 `not_connected`。客户端不得探测旧 URL、旧表或本地缓存来假装能力存在。

## 7. 建库与迁移边界

- 所有 DDL 只允许在受控迁移进程中执行。
- 应用请求处理、后台 worker、登录、同步和功能页面不得执行 DDL。
- 迁移必须具有稳定 migration ID、前置版本、目标版本、代码哈希、开始/完成回执和幂等保障。
- 数据库迁移前必须通过恢复集验证；迁移失败时保持旧数据库原样。
- 禁止在运行时通过 `CREATE TABLE IF NOT EXISTS`、`ALTER TABLE` 或捕获 “no such table” 后补表。
- 禁止 attach 旧数据库后混合读写。
- 禁止在 schema 不匹配时创建空库冒充成功。

## 8. 权威事实与投影

一个业务事实只能有一个权威来源。搜索、向量、摘要、AI 输出、统计、快照和 UI 缓存均为可重建投影。

投影必须带：

- 来源权威对象 ID
- 来源版本
- 投影生成器版本
- 生成时间
- 失效状态

投影丢失只触发重建，不得反向覆盖权威事实。

AI 输出默认是候选。未经用户确认或确定性业务规则，不得写成任务、计划、事件线、权限、身份或其他权威事实。

## 9. 前端完整性边界

完整软件可以先保留全部导航与界面，但每个模块必须明确属于以下状态之一：

- `loading`
- `ready`
- `empty`
- `blocked`
- `failed_retryable`
- `not_connected`

`empty` 只能表示权威查询成功且确实无数据。未建表、接口缺失、权限不足、合同不兼容和同步失败不得显示为空。

## 10. 明确禁止

- 旧表 fallback 或旧接口 fallback。
- 新旧数据库同时读取并拼接结果。
- 通过名称、云地址、当前登录人或第一条记录猜归属。
- 功能首次打开时临时建表。
- 为快速接通功能新增第二权威表。
- 用缓存、索引、AI 结果或统计表恢复权威事实。
- 把旧库路径放进严格新版运行时搜索路径。
- 在本地为组织云业务事实兜底写入后冒充已同步。

## 11. 后续业务域接入

每个业务域接入前必须单独冻结：

1. 权威对象与稳定 ID。
2. 本地与云端的事实边界。
3. 生命周期和权限。
4. 命令、CAS 与幂等。
5. 外部副作用和补偿。
6. 旧数据迁移规则。
7. 五态 UI 与可恢复路径。
8. schema manifest 增量。

未完成上述八项的业务域不得加入严格数据库表白名单。
