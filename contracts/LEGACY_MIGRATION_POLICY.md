# 旧数据进入严格新版的迁移政策 v1

状态：`FROZEN_FOR_IMPLEMENTATION`

## 1. 基本原则

旧库是迁移来源和功能意图证据，不是新版运行时依赖。严格新版不得直接打开、attach、fallback 或双读旧库。

迁移由独立、只读提取器和新版命令导入器完成。导入器只能调用新版权威命令，不允许直接向新版业务表批量写 SQL。

## 2. 四类数据

### A. 可迁移权威事实

同时满足以下条件才可迁移：

- 来源行有明确业务含义。
- 能用稳定 ID 确认云实例、组织和对象归属。
- 生命周期可确定。
- 目标新版合同已冻结。
- 引用对象存在或能按稳定 ID 一并迁移。

迁移时保留旧 ID 作为 provenance，不把旧 ID 直接当新版 ID，除非该域合同明确冻结 ID 延续规则。

### B. 本机独有事实

无云端 ID 的草稿、未同步编辑、原始录音和本机附件先进入只读盘点。只有用户明确选择恢复，且目标域合同已冻结后，才通过新版命令导入。

### C. 可重建投影

以下内容默认不迁移：

- 搜索索引与向量。
- AI 摘要、标签、候选关系和自动生成叙事。
- 统计缓存、图表、列表快照。
- 临时解析中间结果。
- 运行时缓存和旧同步游标。

它们在权威事实迁入后按新版生成器重建。

### D. 有歧义或不安全数据

以下内容只进入 `migration-issues.json`：

- 只能按名称、云地址或当前用户猜归属。
- 同一旧 ID 对应多个组织或对象。
- 父对象缺失。
- 生命周期冲突。
- 旧权限无法可靠恢复。
- 内容被不同表重复承载且无法判断权威来源。
- 外键异常影响归属。

这类数据不得自动迁移、删除或归并。

## 3. 身份与账号

- 云实例和组织必须通过既有稳定 ID 或人工签署的映射确认。
- 手机号和邮箱只作为登录标识，不作为 principal ID。
- 唯一匹配的登录标识可以绑定既有 principal；多匹配必须阻止并人工处理。
- 密码只迁移可验证的强哈希，不迁移明文。
- access token、refresh token 和旧 session 不迁移；切换严格新版后重新登录。
- 管理员、成员、部门和权限必须按成员关系迁移，不能从头衔名称猜测。

## 4. 组织 AI 配置

- 只迁移经管理员确认的当前组织配置。
- API Key 必须在迁移过程中重新加密或由管理员重新上传。
- 不把客户端缓存 Key、指纹或旧代理状态当云端配置。
- 旧组织身份与目标组织不完全匹配时不得复用。

## 5. 业务数据

任务、客户、项目、事件线、文档、报告等业务域在各自物理合同冻结前一律不迁入创世数据库。

每个域必须另行提供：

- 来源表和权威字段。
- 稳定 ID 映射。
- 组织与 sandbox 映射。
- 生命周期映射。
- 权限映射。
- 引用拓扑。
- 附件清单和哈希。
- 导入命令和回执。
- 抽样核验与回滚方式。

不得为兼容旧数据临时恢复旧表。

## 6. 附件与文件

- 先盘点路径、大小、SHA256、媒体类型和来源对象。
- 文件名只用于展示，不用于归属。
- 内容哈希相同不等于业务对象相同；去重只处理物理 blob，业务引用仍独立。
- 来源对象不明确的文件进入隔离清单。
- 迁移后必须验证对象可读取，不能只验证数据库行存在。

## 7. 迁移回执

每批迁移必须记录：

- migration run ID
- 来源 recovery set 和数据库哈希
- 目标 schema/build identity
- 规则版本
- 输入、成功、跳过、冲突和失败数量
- 每条来源 ID 到目标 ID 的映射
- 操作者和时间
- 校验结果

迁移必须可重复执行且不重复创建对象。

## 8. 回滚

回滚不把新库降级成旧结构。若导入批次失败：

- 停止后续批次。
- 保留来源备份。
- 用命令回执识别本批创建对象。
- 按目标域合同执行补偿或废弃。
- 不用旧库覆盖新库。

## 9. 当前明确暂缓

- 客户、项目与事件线的最终物理边界尚未冻结。
- 现有混合本机库存在外键异常，不能整体复制。
- 现有益语云与星丛云仍是旧/混合运行库，只作为备份和迁移来源。
- 旧报告存储、旧权限旁路和旧事件线自动关联不得进入新版。
